# 项目开发日志与 GitHub 发布指南

## 1. 项目目标

本项目回答一个面向 FMCG 零售与快消业务的决策问题：在促销预算有限时，
应该把资源投入哪些品类、活动和客户群，并怎样区分“销售相关”“促销增量”
和“假设条件下的回报”。

项目不是只做一张仪表板，而是形成一条可复核的分析链：

`受限原始数据 → Python 清洗与建模 → 质量检查 → BigQuery SQL 分析层 → Power BI 决策展示 → Git/GitHub 版本管理`

为避免把不同性质的数字混在一起，所有核心结果分为四类：

| 证据标签 | 含义 | 示例 |
|---|---|---|
| `observed_behavior` | 从交易、活动和兑换记录直接汇总的事实 | 销售额、客户数、优惠券兑换渗透率 |
| `model_based_assignment` | 由算法生成的客户标签 | K-Means 客户分群 |
| `quasi_experimental_estimate` | 匹配与双重差分得到的促销增量估计 | 每次促销事件增加约 0.36 件 |
| `assumption_only_scenario` | 依赖成本、毛利率和放大倍数的情景 | ROI、净贡献、盈亏平衡倍数 |

## 2. 使用的平台与工具，以及为什么这样选

| 平台或工具 | 在项目中的作用 | 采用原因 |
|---|---|---|
| dunnhumby Complete Journey | 提供匿名家庭、交易、商品、活动和优惠券数据 | 数据结构接近真实零售业务，但属于受限来源，因此只在本地及私有云端使用 |
| Python、pandas、PyArrow | 清洗、连接数据并生成 Customer 360、留存、促销面板和 Power BI 输入 | 适合可重复的数据处理、自动质量检查和 Parquet 文件读写 |
| scikit-learn | K-Means 分群、标准化和稳定性评估 | 不只给出客户标签，还能用 silhouette、ARI 等指标检验模型是否稳定 |
| 匹配、DiD、事件研究与 bootstrap | 评估促销增量 | 将“促销期间销量较高”与“促销可能造成的增量”分开，并检查平衡、预趋势和安慰剂结果 |
| Google BigQuery Sandbox / GoogleSQL | 建立云端 SQL 数据质量层和分析集市 | 展示仓库型 SQL 能力；让数据质量、客户、优惠券、促销和高管 KPI 在云端可审计地重算 |
| Power BI Desktop / PBIP / DAX | 制作四页交互式业务报告 | 将观察值、模型结果、准实验估计和 ROI 假设分别呈现；PBIP 文本格式也便于 Git 审查 |
| Git 与 GitHub | 保存版本、记录独立贡献并形成作品集 | 让代码、SQL、方法、验证结果和仪表板结构可追踪，同时通过 `.gitignore` 阻止受限数据进入公开仓库 |

## 3. 实际完成过程

### 阶段 A：梳理来源、范围与发布边界

1. 保留原项目的 MIT 许可和作者归属，新增 `THIRD_PARTY_NOTICES.md`。
2. 确认 dunnhumby 数据只能作为本地或私有分析输入；`data/raw/` 不进入 Git。
3. 把项目问题拆成描述、增量和决策三层，避免直接把相关性写成因果关系。

### 阶段 B：Python 数据基础与质量控制

1. 清洗并连接交易、商品、活动、优惠券和兑换数据。
2. 生成交易级、商品级、家庭级和产品－门店－周级中间表。
3. 对行数、主键、缺失、孤儿记录、非法值和销售额对账运行自动检查。
4. 受限的原始表、Parquet 中间表和家庭级结果保留在本地；公开仓库只保存代码、方法和聚合结果。

### 阶段 C：Customer 360、RFM、Cohort 与 K-Means

1. 以“一户一行”建立 Customer 360，计算最近购买、购买频次、消费额、客单价、活跃周数、折扣与优惠券行为。
2. 用固定 30 天周期建立首次观察购买 cohort；P00 标记为左删失，少于 30 户的 cohort 不用于主要比较。
3. 比较 K=2 至 K=8，并结合可解释性选择 K=3；再做随机种子与时间窗口稳定性检验。
4. 最终形成 High-Value Frequent、Developing Occasional、Dormant Low-Value 三个决策型群组。

### 阶段 D：优惠券和商业决策层

1. 修正优惠券指标的分母：`coupon` 表中的 124,548 行是“优惠券－可用商品映射”，不是发券次数。
2. 使用 7,208 个唯一“家庭－活动”定向暴露作为分母，得到 12.33% 的定向家庭兑换渗透率。
3. 对活动类型、客户群和品类制作聚合表现表，但不把非随机投放差异解释为客户群的因果反应。

### 阶段 E：促销增量评估

1. 构造促销前后各四周的事件窗口，并排除重叠活动。
2. 在同品类中为处理事件匹配未暴露对照，使用共同支撑和距离阈值控制可比性。
3. 运行 matched Difference-in-Differences、事件研究、产品级 cluster bootstrap、预趋势和安慰剂检查。
4. 将结果限定为准实验估计，而不是随机试验结论。

### 阶段 F：Power BI 决策报告

建立四个页面：

| 页面 | 回答的问题 |
|---|---|
| Executive Summary | 销售、品类、兑换和管理结论是什么？ |
| Customer Growth & Segmentation | 哪些客户创造价值，他们是否仍保持活跃？ |
| Promotion Incrementality | 促销带来了多少可归因的短期增量？ |
| Budget Scenario Planner | 在不同毛利、成本、规模和预算假设下，什么时候能够回本？ |

每页使用证据类型标签，ROI 页面使用单选参数，保证卡片、折线和说明文本来自同一组假设。

### 阶段 G：BigQuery 云端 SQL 层（2026-10-21 完成）

1. 在 BigQuery Sandbox 的 `asia-southeast1` 区域创建私有 Dataset：`fmcg_analytics`。
2. 上传九张本地受限源表；Dataset 未设为公开，文件也未上传 GitHub。
3. 按顺序运行 `sql/bigquery/00_source_contract.sql` 至 `05_executive_kpis.sql`：
   - 00：源表契约、粒度和预期行数；
   - 01：数据质量与对账；
   - 02：客户 RFM 与分群表现；
   - 03：优惠券活动、类型与客户群表现；
   - 04：匹配促销事件和增量效果；
   - 05：高管 KPI 汇总。
4. 六个脚本均成功执行，云端结果与 Python 和 Power BI 的指标一致。详细证据见
   `outputs/validation/bigquery_cloud_run.md`。

## 4. 面对结果，可以得出什么结论

### 4.1 经营结构

- 全店观察销售额约为 **$8.06M**，饮料销售额约为 **$661K**，占全店 **8.2%**。
- 碳酸软饮占饮料销售约 **59.2%**，果汁占约 **22.8%**；两者是饮料业务最重要的收入来源。
- 因此，后续促销试验优先放在碳酸软饮和果汁，比平均分散预算更有依据。

### 4.2 客户价值与留存

- **High-Value Frequent** 占家庭数 **45.2%**，贡献全店观察收入 **79.0%**，价值高度集中。
- 可比较 cohort 在首次观察购买后第 12 个 30 天周期仍约有 **81.1%** 活跃；但样本是高频购物者，P00 又存在左删失，不能把该数值解释为所有新客的真实长期留存率。
- 业务含义是：高价值客户应优先做留存；Developing Occasional 适合做再激活或频次提升测试；Dormant Low-Value 不宜在证据不足时大量投放。

### 4.3 优惠券表现

- 有效的总体定向兑换渗透率为 **12.33%**。
- High-Value Frequent 的观察兑换渗透率为 **13.78%**，Developing Occasional 为 **4.13%**。
- Type A 活动的平均渗透率约 **14.2%**，高于 Type C 的 **9.1%** 和 Type B 的 **7.8%**。
- 这些是观察到的投放与兑换差异；由于活动分配不是随机的，不能仅凭这些数字断言某群体“对优惠券更敏感”。

### 4.4 促销增量

- 423 个匹配事件显示，促销周每个产品－门店事件约增加 **0.36 件**和 **$0.55** 收入。
- 单位增量的 95% bootstrap 区间约为 **[0.14, 0.65]**，p 值约为 **0.007**；预趋势检验 p 值约为 **0.442**，没有发现明显的处理前分化。
- 碳酸软饮约增加 **0.39 件/事件**，果汁约增加 **0.27 件/事件**，两类均适合开展受控扩张测试。
- 增量主要集中在促销周，后续区间穿过 0，因此目前没有充分证据证明效果持续。

### 4.5 ROI 与预算

- 在基准情景（点估计、10 倍放大、30% 毛利、每事件 $5、预算 $1,000）下，净贡献约 **-$671.99**，ROI 约 **-67.2%**。
- 盈亏平衡需要约 **30.5 倍**的 panel-to-store 放大倍数。
- 因为真实毛利、执行成本和全门店覆盖倍数不可用，这不是实际财务亏损结论，而是一个假设压力测试。
- 当前建议不是立即扩大整体预算，而是先在碳酸软饮和果汁中做可控试验，同时取得真实毛利与执行成本后再重新估算 ROI。
